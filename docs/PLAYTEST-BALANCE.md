# 玩法与道具试玩记录

适用范围：产品化 Issue #17。本文把“收集家庭反馈后调整配比”变成可重复执行的流程。当前八种道具在自定义局每种各一张；亲子轻松局使用起飞卡 2、加速卡 1、幸运骰 1、护盾 2、救援卡 1、团队护航 1，不包含攻击道具。实际规则以新局显示的规则卡为准。

## 先收集，再调参

当前战绩和管理员只读对局记录能提供掷骰、起飞、抵达、撞回与道具使用次数。它们只能说明发生了什么，不能单独证明某张道具太强或太弱；不要根据单局输赢改规则。每次试玩后请记录：

| 字段 | 记录方式 |
| --- | --- |
| 玩法、席位数、棋盘、是否联网 | 选择规则，不记录房间链接、Cookie 或玩家档案编号 |
| 参与者感受 | 每人选“有趣 / 普通 / 不太有趣”，并可补一句具体感受 |
| 道具反馈 | 写道具名和发生的局面，例如“护盾一直没用上”，不写儿童姓名 |
| 对局结果 | 从家庭记录读取完成时长和每人用卡/抵达/撞回数量；无日志则标记缺失 |
| 版本与日期 | 记录提交短 SHA 和试玩日期，方便比较调参前后 |

不要保存原始语音、儿童姓名、联系方式或邀请凭证。需要提交 bug 时，附不含个人信息的版本、玩法、重现步骤和是否可重复。

## 调整门槛

1. 至少来自 3 个家庭、10 局自然结束对局，且同一种道具的反馈指向同一问题，再提出配比修改；这是本项目的工作门槛，不是统计学结论。
2. 一次只改一个变量，例如只调整亲子模式护盾数量；经典规则、骰子随机性和其他道具保持原样。
3. 修改前后各跑同样的 2/3/4 席、同屏/联网和不同机器人难度矩阵。每局使用独立房间、真实 Go 掷骰和规则，不编辑存档制造结果。
4. 比较完成局数、耗时、抵达/撞回/用卡计数与玩家主观反馈。若只有次数变化、玩家体验未改善，就恢复旧值并记录原因。
5. 规则变化必须同时更新规则卡、README、测试和 Issue；保留旧存档兼容，且不能改变已经开始的对局。

## 首个新挑战：星河救援

“星河救援”是 2～4 人合作玩法，每人仍有两架飞机，各自先送达一架；最后一位队员完成目标时，全队共同获胜。机器人可占一个席位，所有动作仍走服务端 Go 规则。挑战模式可在创建游戏时选择，可同屏，也可用邀请房间联机；没有修改随机骰子、起飞规则或道具库存。

首轮自动演练以两位真人席位、随机骰子、合法走法、刷新后结算/回顾、同配置再玩和两台浏览器邀请开始/入座为检查项。自动演练不能替代不同家庭对挑战难度与趣味性的持续反馈。

反馈记录通过产品 Issue 关联的小 PR、版本化 QA 记录和家庭实际反馈累积。暂时没有足够多样本支持重新配平道具，因此本轮保留现有库存，避免无证据调整。
