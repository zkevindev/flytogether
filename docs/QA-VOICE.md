## 真人实机

在本机 Chrome 使用真实麦克风与扬声器，实际输入「小灵同学」「使用起飞卡」「掷骰子」「让小熊号起飞」。服务端棋局版本 1 → 2 → 3 → 4，起飞卡实际启用，本次随机骰子为 5，小熊号进度从 -1 到 0，随后轮到爸爸。用户确认三步成功、语音清楚，未将播报误识别为指令；另确认在介绍规则时插话后，旧播报停止并回答了当前玩家。

测试中曾将「使用起飞卡」转写为「使用积分卡」，用户重说后成功；不把这一轮有限样本当成所有口音、噪声环境下的识别率保证。未测家长与孩子完整对局，也未测多种真实手机。

## 浏览器与真实平台（当前无需唤醒）

Chrome 默认自动播放策略下，不点击语音按钮，使用合成 WAV 作为浏览器虚拟麦克风，经过真正的 getUserMedia、AudioWorklet 重采样、浏览器 WebSocket、Go 网关和真实灵矽平台。没有拦截平台回复或指定骰子结果，也没有设置绕过声音策略的启动参数。

- 不带唤醒词，首次「现在轮到谁」得到回复且不改棋局；随后「使用起飞卡」「请帮我掷骰子」「让小熊号起飞」均被接受并执行。
- 两轮真实随机点数分别为 4、1，版本 1 → 2 → 3 → 4。直接对话没有原先的 30 秒门控窗口。
- 连续查询与「不要掷骰子」保持版本 4。
- 真实断开后所有麦克风轨道停止，重新启用并完成真实平台握手，棋局 ID 和版本保留。
- 首批 5 个回复，从最终转写到首段 PCM / 浏览器播放调度耗时：745、807、969、746、2038 ms，中位数 807 ms。它不含说话时长和转写前等待，也不是扬声器端的声学测量，不据此计算稳定的 P95。

早期自动唤醒界面截图保留在历史记录；当前网页已去掉唤醒词编辑和待唤醒操作。真实麦克风记录是此前的有限真人样本，本轮无需唤醒回归使用合成 WAV。

## 故障与生命周期

独立的浏览器回归使用真实 Chrome 麦克风采集和 AudioWorklet，但拦截应用的语音 WebSocket 握手，避免依赖平台来判断前端状态恢复。验证无按钮自动连接、刷新自动连接、手动关闭后刷新不重启、重新开启、暂停释放轨道、继续自动连接、新局关闭旧轨道、断线释放与手动重试、结束释放，以及模拟权限拒绝后不反复请求且点击玩法可用。

新增网关集成测试使用实际 TLS/WebSocket 连接与受控上游，故意在取消后或新局开始后投递旧 response 的工具调用。新的掷骰只结算一次，旧工具不能修改新回合或新棋局。该测试模拟上游时序，不表示真实网络的所有故障组合都已测完。

语音客户端十四项模拟回归还覆盖权限迟到、握手关闭、取消、迟到音频字幕、待唤醒、主持人主动播报、断线清理、自动播放被拦截的超时，以及解锁挂起时仍能处理麦克风授权。

## 快速生成与播放积压

旧版将所有音频直接排入 AudioContext，排队超过 12 秒即断线，正常长回复也可能误触发。回归覆盖：

- 真实 Chrome 中将 24 秒 PCM 瞬间送达，完整播放 240 个短片段；预排最大约 348ms，麦克风轨道持续 live，无需重连。这项使用受控语音 WebSocket，测试浏览器播放行为。
- 实际 AudioContext suspend/resume 后继续播放；打断清空未排与已排音频，并丢弃旧 response 的迟到数据。
- 模拟超过 90 秒缓冲上限，仅取消当前响应，保留连接和麦克风；下一条直接指令可正常播放。
- 真实灵矽完整操作链另行复跑通过，覆盖现有 PCM 队列和实际浏览器采集；本次六条从转写到首段 PCM 为 898、888、786、748、907、1831ms，无积压断线。
