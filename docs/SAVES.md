# 存档、续玩与备份

单个 Go 实例使用 SQLite，动作、道具库存、房间席位、邀请、当前浏览器映射与点击命令去重在同一事务提交，成功后才推送和返回结果。保存失败返回 `SAVE_UNAVAILABLE`，本次操作不生效；机器人保存失败会暂停。保存时间表示最近一次持久化变更，不是 WebSocket 心跳时间。

服务重启后，未结束的对局恢复为暂停。骰子、合法走法、道具、本局统计和原席位保留；麦克风、旧动作授权、教练建议和连接状态重新建立。机器人不会在恢复时偷偷行动，房主确认继续后才恢复调度。首页展示保存时间、继续入口和房主删除入口，删除会关闭整个房间，不能撤销。

## 配置与身份边界

- `SAVE_PATH`：本地默认 `data/games.db`；安装脚本默认 `/var/lib/flytogether/games.db`，独立于每次发布目录。
- `SAVE_RETENTION_HOURS`：默认 168 小时，可设 1～8760；无在线连接且超期的房间会清理，启动也会清理过期记录。
- 浏览器身份 Cookie 在访问会话/家庭记录时续期一年；房间闲置保存期仍为7天。清除 Cookie、换浏览器或换设备无法找回原席位。邀请链接是入座凭证，不能冒充已经占用的席位。
- 数据库含席位凭证与邀请，文件权限 `600`，备份同样敏感；不提交到 Git，不存原始录音或 API Key。
- 仅支持一个 Go 实例独占同一业务数据库；此版本不支持多实例共享 SQLite、全局排行榜或账号找回。

首次从旧的纯内存版本升级时，旧进程中没有落盘的对局无法迁移。启用本版后创建的游戏支持后续更新和重启续玩。

## 在线备份

使用 Python 3 自带 SQLite backup API，可包含 WAL 中已提交的数据，不要在运行中只复制 `.db` 文件：

```sh
python3 scripts/save_backup.py \
  --database /var/lib/flytogether/games.db \
  --output /安全备份目录/games-日期.db
```

脚本拒绝覆盖现有备份，执行完整性检查，以权限 `600` 原子写入。需要具备数据库与目标目录的读取/写入权限；备份应放在服务器之外另存一份。目前提供手动备份工具，未配置自动定时备份。

## 恢复

1. `systemctl stop flytogether`，确认旧进程退出，保存当前 `.db`、`-wal`、`-shm` 文件为故障现场。
2. 对备份执行 `python3 -c 'import sqlite3,sys,pathlib; print(sqlite3.connect(pathlib.Path(sys.argv[1]).resolve().as_uri()+"?mode=ro",uri=True).execute("PRAGMA quick_check").fetchone()[0])' /安全备份目录/games-日期.db`，应返回 `ok`。
3. 在服务停止状态移走现有三个文件，再将备份复制到配置的 `SAVE_PATH`。不要把旧 WAL/SHM 留在新数据库旁。
4. 将数据库属主设为 `flytogether:flytogether`、权限设为 `600`，所在目录应允许该服务用户写入。
5. `systemctl start flytogether`，检查 `/readyz`，用原浏览器回到首页，确认保存时间、玩家、道具与骰子，再继续。

SQLite 数据库整体损坏或 schema 比程序新时启动失败并保留文件，应检查服务日志和备份，不能删除数据库当作修复。单条房间记录校验失败时会隔离到 `quarantine` 表并记告警，其旧席位映射不再有效；网页可新建游戏，不能把损坏棋局当正常棋局继续。清理过期记录不等于擦除备份，备份保留和删除由运维管理。

实际进程重启、写入失败、去重与恢复范围见 [存档与声音验收](QA-RELIABILITY.md)。


## 预设规则版本保护（#27）

数据库格式现为3，旧存档按原自定义规则迁移，亲子/经典预设与库存随棋局保存。旧程序无法理解新的起飞规则时会拒绝打开较新的数据库；回滚至不支持预设的程序，应先停止服务并按上文恢复升级前备份，不能只替换旧二进制。恢复会回到备份时刻。此次上线前已完成在线备份与完整性核对。

## 家庭资料与战绩（#29）

`family_profiles` 以浏览器会话隔离，保存最多12位昵称和内置头像；不保存照片或录音。房间中仅保留本局选中的档案绑定和头像快照，联网快照仅向本人返回自己的绑定。API不允许借用其他浏览器的档案ID。修改资料后新建对局生效；当前局/同配置再玩保留原配置，删除档案不改写旧记录。

`family_history` 与房间的最终动作处于同一事务，按浏览器和游戏ID去重；只记录自然结束且非演示的胜负，保留规则、名字、头像、五项累计统计及本人档案绑定。每个浏览器可见最近50局和总局数，档案统计也仅聚合这50局。记录独立于房间保留，删除房间或闲置清理不会删除历史。

清空历史会将当前浏览器的历史内容置空，保留最小去重收据（浏览器标识、游戏ID、完成时间），防止旧结束棋局再次保存时恢复历史；其他浏览器的记录不受影响。Cookie失去后没有账号入口找回，服务端不会因清Cookie自动删除资料；完整数据库备份也由运维自行保留/删除。当前不提供全库隐私擦除或跨设备迁移界面。

schema3迁移增加独立资料与历史表，不删除原存档。升级前须在线备份；回滚不理解新格式的旧程序时，停止服务后恢复对应版本备份，不能直接替换二进制。
