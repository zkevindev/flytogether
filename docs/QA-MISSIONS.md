# 星际救援主题与合作任务验收

## 自动化覆盖

Go 规则和存档回归：

```sh
go test ./internal/game ./internal/room
```

覆盖任务白名单、开始与进度、重复刷新幂等、玩家贡献校验、自然完成/失败、手动结束、SQLite 恢复，以及同配置再玩的任务重置。另有 `go test -race ./...` 和 `go vet ./...` 全仓检查。

Chrome 多设备回归需要已构建的 Go 服务；通过 `QA_BASE_URL` 指定地址：

```sh
QA_BASE_URL=http://127.0.0.1:8080 \
QA_OUTPUT_DIR=/tmp/flytogether-coop \
npm --prefix web run test:coop:browser
```

测试通过真实创建入口完成一局星河救援、服务端随机骰子和合法走棋，验证任务完成、刷新恢复和同配置再玩重置。再创建双人联网信号任务，让桌面房主、390px 手机玩家和手机观众使用各自隔离会话；一个真人达到三次已提交掷骰后，三端都显示 `1/2`。接着模拟手机断网，让另一席在其离线期间完成任务，手机恢复连接后同步到 `2/2`；重复提交同一个操作编号不会增加棋局版本，刷新手机席位后任务仍为 `2/2`。回归还核对轻量平面、减少动画和总静音偏好。所有骰点、位置和任务进度均由正式服务端生成，没有注入棋局状态。

## 权限边界

任务进度在 Go 已提交命令后由玩家累计统计派生；MCP 只读工具不接收任务修改或游戏写操作。工具凭据短时绑定当前房间/会话并哈希存储，失败或迟到的工具结果不得转成成功答复。Realtime MCP 的异步工具导入、完成、失败、迟到及续答测试见 [QA-MCP](QA-MCP.md)。
