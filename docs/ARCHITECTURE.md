# 一起飞 FlyTogether · 项目架构设计

- 版本：0.1
- 日期：2026-10-24（Asia/Shanghai）
- 状态：网页与 Go 服务已部署；真实灵矽 Realtime 的合成语音查询、掷骰与音频回复已验证；真实麦克风操作和打断已由用户确认，家庭与多设备试玩继续验收
- 约束：一人开发，比赛三天两晚，无专用硬件，后端 Go

## 1. 项目名称与定位

**中文名：一起飞。英文名及代码标识：FlyTogether / flytogether。**

项目副标题：会说话的家庭飞行棋搭子。

产品介绍：让家长和孩子在一块屏幕前，通过自然对话玩飞行棋。灵矽担任主持人，理解操作、解释规则、回应棋局变化；需要时加入一个 AI 玩家。Go 服务掌握规则与真实棋局。

核心用户是同处一室的家长与孩子。设计假设是玩家能够辨认棋子标记、表达简单选择；适龄体验需要实际试玩验证。使用电脑或平板的屏幕、麦克风和扬声器，无需购买专用设备。

比赛展示主线：孩子说“我想撞爸爸的飞机”，系统结合真实棋局给出合法选择，玩家确认后执行，随后准确讲解结果。

## 3. 用户流程与交互

### 3.1 开始一局

1. 家长打开网页，创建本地家庭房间。
2. 设置房间名、棋盘路线、2～4 个席位和昵称；决定是否加入 AI，并选择轻松、普通或挑战难度。
3. 进入准备阶段，显式点击“开始游戏”；可暂停、继续或结束当前局。
3. 选择完整模式或快速模式，查看固定规则摘要。
4. 同意浏览器麦克风权限并测试一次说话；也可以直接点击试玩。
5. 开局后突出显示当前玩家、掷骰按钮和可选棋子。

家庭共用一个本地操作者会话。轮到谁由棋局决定，不根据声音猜测身份；这不提供远程多人场景中的身份保障。

### 3.2 每回合

掷骰 → 显示点数 → 高亮可走棋子 → 选择并执行 → 展示结果 → 处理 AI 回合或转交下一位。

只有一个合法走法时，Go 可以自动执行并说明；多个走法时由玩家选择。查询和规则讲解不消耗游戏操作。

### 3.3 语音与视觉

- 每架棋子都有稳定 ID、序号和图案昵称，如“小熊号”；颜色只是辅助。
- “最前面”按本方路线进度判断；并列时列出候选，不随机代选。
- “撞爸爸”先查询目标与合法走法；无法做到时解释原因。
- 语音操作与点击按钮共享同一套可走方案。
- 进入对局后自动连接，首次需允许麦克风；直接对话，无唤醒词或 30 秒窗口，由服务端 VAD 识别说话起止。
- P0 在一次语音请求结束前禁止提交下一次语音或并行点击写操作，避免无法关联的迟到指令。
- “停止播报”只停止声音；已执行的棋步保留。P0 不实现悔棋或通过打断撤回动作。
- 重点事件才播报，移动中不逐格念数；讲解以短句为主。

## 4. 灵矽能力依据与接入边界

下表区分文档事实与项目决策。所有“已确认”均指文档描述，尚非实际联调结果。

| 项目 | 文档事实 | 项目决策 / 待验证 |
| --- | --- | --- |
| 实时语音 | Realtime WebSocket 支持流式音频、转写、语音输出与打断 | 浏览器经 Go 代理连接；凭据留在服务端 |
| 会话配置 | 建连后由服务端发送实时会话音频、VAD 和提示词配置 | 模型从部署配置读取，不接受浏览器传入 |
| 游戏工具 | Realtime 会话支持工具定义与调用事件 | Go 执行本项目的查询、掷骰、移动工具，并以棋局状态为准 |
| 语音轮次 | 服务端 VAD 识别说话起止，可在播报时开始新输入 | Go 只在转写被接受后签发单次动作授权并请求回复 |
| 页面音频 | 浏览器麦克风经 AudioWorklet 重采样为 16 kHz PCM；上行到 Go | Go 转成 Realtime 音频事件；返回 PCM 音频增量由浏览器播放 |

事实来源：[WebSocket 与 Realtime 协议](https://linx.qiniu.com/docs/xrobot/platform/websocket)。

服务端 API Key 与浏览器会话分开管理。浏览器只连接本项目的 Go 网关；Go 通过 `Authorization: Bearer` 请求头完成上游授权，WebSocket 子协议使用 `realtime`，API Key 不下发到页面。Realtime 模型名和凭据由本机或服务器环境配置。

## 5. 总体架构与技术选择

采用一个 Go 进程承载游戏、浏览器 API、Realtime 语音代理和工具调用，按功能分包。数据库、消息队列和微服务均不是 MVP 依赖。

~~~mermaid
flowchart LR
    U["家长与孩子"] --> W["网页：棋盘、字幕、录放音"]
    W <-->|"游戏 HTTP / WebSocket"| G["Go：房间与动作服务"]
    W <-->|"独立语音 WebSocket"| V["Go：灵矽连接适配"]
    V <-->|"上游语音 WebSocket"| L["灵矽：语音、对话、工具选择"]
    L -->|"Realtime 工具调用事件"| V
    V -->|"游戏工具"| G
    G --> R["纯 Go 规则引擎"]
    G --> A["Go AI 策略"]
    G --> S["SQLite 房间与命令去重"]
    V --> B["浏览器语音会话 / 房间映射"]
~~~

| 决策 | 选择及原因 |
| --- | --- |
| 前端 | React + TypeScript + Vite；Three.js 棋盘与编号标记，2D 棋盘作为降级 |
| Go HTTP | 标准库 net/http；业务逻辑不依赖 HTTP 类型 |
| WebSocket | 候选 coder/websocket；游戏与音频用两条连接，防止音频积压阻塞棋局 |
| 工具调用 | 在 Realtime 会话声明项目游戏工具，由 Go 网关处理 function call 事件 |
| 状态 | Go 为唯一真实来源，前端负责呈现，不保留第二套权威规则 |
| 存储 | SQLite 事务保存，确认前落盘，重启暂停，原 Cookie 恢复席位 |
| API 类型 | 简单 REST 契约与 TypeScript 类型；初版人工对照，后续可生成客户端 |
| 认证 | 浏览器使用不透明会话 Cookie；灵矽 API Key 仅由 Go 服务端读取；不引入用户账号 |
| 对手 | 确定性规则策略选择合法动作；不额外接一个模型控制走棋 |

依赖依据：[coder/websocket](https://github.com/coder/websocket)。

## 6. Go 模块职责

| 模块 | 职责 | 边界 |
| --- | --- | --- |
| game | 纯规则、合法走法、动作结果、胜负 | 不访问网络、音频、模型或 HTTP |
| room | 房间生命周期、版本、命令去重、串行提交、状态广播 | 所有写动作唯一入口 |
| opponent | 在合法候选中评分，安排 AI 回合 | 不能修改随机骰子或绕过规则 |
| linx | Realtime 上游连接、会话初始化、音频事件与工具调用适配 | 不解释飞行棋规则 |
| voice | 浏览器语音会话、交互状态、播报队列 | 不直接移动棋子 |
| voice tools | 将实时会话的工具调用映射到 room 服务 | 不在工具处理函数中重写规则 |
| transport | 浏览器 HTTP / WebSocket、Cookie、错误转换 | 不拥有业务状态 |

同一房间写操作使用短临界区串行执行；网络和模型等待不持有房间锁。先计算并提交棋局，再广播结果。广播失败不回滚已完成的棋步。

## 7. 固定规则：family-v1

以下是项目主动选择的家庭规则，不宣称覆盖所有飞行棋变体。规则一经开局固定，并在界面可查。

| 项目 | family-v1 |
| --- | --- |
| 人数与棋子 | 2～4 方；完整模式每方 4 架，快速模式每方 2 架 |
| 起飞 | 掷到 6 可选一架从机库到起飞位，消耗本次点数；起飞位下次移动才进入公共航线 |
| 前进 | 依棋子所属路线前进点数；骰子由 Go 的随机源生成 |
| 六点奖励 | 掷到 6，处理完本次结果后仍轮到当前玩家；不实现三连六额外惩罚 |
| 无可走棋子 | 返回明确原因，自动完成本次点数处理；是否继续依六点奖励规则决定 |
| 同色跳格 | 普通移动落在配置的同色跳格起点时，执行一次配置跳跃 |
| 飞行 | 普通移动或一次跳格后到达飞行起点，执行一次配置飞行；飞行后不再触发跳格 |
| 撞机 | 仅在本次动作最终落点判定公共格碰撞；经过的棋子不受影响 |
| 叠子 | 同方可叠放；最终落点的其他方棋子全部回机库，不实现叠子封路 |
| 安全区 | 机库、起飞位、本方终点航道和终点不参与公共格撞机 |
| 终点 | 需要精确点数；超出终点的走法不合法；不采用反弹规则 |
| 获胜 | 完整模式率先全部到达；快速模式率先一架到达；首位获胜后结束一局 |

每局选择一个棋盘规格。服务端为各规格保存公共格长度、终点跑道、跳格和飞行位置；棋盘布局只影响视觉呈现与路线长度，不改变同一局内固定的 family-v1 动作结算规则。

动作结算顺序：普通位移 → 最多一次同色跳格 → 最多一次飞行 → 最终落点撞机 → 到达终点 → 胜负 → 六点奖励 / 下一玩家。

### 7.1 趣味道具：family-props-v2

新建网页对局默认启用道具，开局设置可关闭并使用原 family-v1。每位玩家开局各有起飞卡、加速卡、幸运骰、炸弹、护盾一张，每次掷骰前最多使用一张，使用即消耗库存并增加棋局版本。AI 共用同样的库存和规则。起飞卡需要指定己方机库飞机，直接移动到起飞位并占用当前掷骰道具位；加速和幸运骰效果持续到本次点数处理完成，在额外回合、下一玩家或胜负确定时清除。

| 道具 | 服务端效果 |
| --- | --- |
| launch / 起飞卡 | 指定一架己方机库飞机后立即移到起飞位，不掷骰；后续实际掷出六点才获得奖励回合 |
| boost / 加速卡 | 对已经离开机库的飞机，基础步数为实际骰子 +2，再按同色跳格和飞行结算；不能越过终点 |
| luck / 幸运骰 | Go 用随机源掷两次取较大值，`dice_rolls` 保留两次结果，`dice` 保存实际选中的点数 |

| bomb / 炸弹 | 通过 `piece_id` 指定对手公共航线飞机；有盾先破盾，无盾回机库 |
| shield / 护盾 | 指定己方未受保护的公共航线飞机，`shield` 持续到抵挡一次炸弹或撞机 |

炸弹和护盾立即生效，但同样占用本次掷骰前的道具槽。护盾不随回合清除；机库、起飞位和终点航道不可选。撞机走法区分 `captured` 与 `blocked`，后者只清除护盾。

`props_enabled`、`active_prop` 与每位玩家的 `props` 库存随快照下发。经典模式、已掷骰、库存耗尽、重复叠加及不适用的用卡请求都返回错误且不修改状态。使用卡与掷骰是两个独立动作；语音一轮授权只允许完成其中一个。

### 7.2 棋盘布局

参考[传统飞行棋布局](https://lzltool.com/fxq)，由本项目统一生成四角机场、连续公共航线、起飞位、终点跑道和中央骰子坐标。52 格与 84 格沿用 Go 的公共格索引；路线格颜色按全局索引取模，与同色跳格规则一致。环形路线也使用同一份布局投影绘制格子和棋子。

同一飞机只绘制一次，机库分开停放，同格飞机显示分离的编号标记。窄屏让棋盘占满主列，提供棋盘内放大滚动、道具快捷入口和操作区的大按钮。几何回归检查路线长度、连续性、机场不遮挡公共格及同格棋子的可辨认位置。

规则引擎只接受有效起点和当前点数，返回最终快照及有序事件，如 launched、jumped、flew、captured、finished。语音说明、动画和走法预览共用这些结果。

## 8. 状态模型与一致性

### 8.1 核心对象

| 对象 | 主要字段 |
| --- | --- |
| Room | room_id、host_session_id、match、voice_binding、room_seq |
| Match | game_id、ruleset_id、board_id、mode、status、version、turn_id、phase、current_player_id、dice |
| Player | player_id、nickname、color、human/ai、pieces |
| Piece | piece_id、label、status、route_progress；cell_id 由地图计算 |
| Command | command_id、source、game_id、turn_id、expected_version、action、arguments |
| CommandResult | command_id、accepted、version、snapshot、events、error |
| VoiceBinding | browser_session_id、linx_session_id、room_id、game_id、binding_epoch |

Room 和 Match 分开：同一家庭房间可以重新开局，每局使用新的 game_id。客户端引用旧局的写操作全部拒绝。掷骰、移动和用道具还需匹配版本；暂停和结束允许作用于同一局的最新版本，避免 AI 刚走一步导致用户无法暂停。

### 8.2 回合状态

~~~mermaid
stateDiagram-v2
    [*] --> WaitingRoll
    WaitingRoll --> WaitingMove: 掷骰且存在多个合法走法
    WaitingRoll --> Resolving: 唯一走法自动执行或无走法
    WaitingMove --> Resolving: 选择合法棋子
    Resolving --> WaitingRoll: 六点奖励或下一玩家
    Resolving --> Finished: 达成胜利条件
    Finished --> [*]
~~~

Resolving 是服务端一次原子动作内部的瞬态；前端可以还在播放动画，但不能据此修改真实回合。游戏快照的 phase 以服务器稳定状态为准，动画期间前端暂时禁用写操作。

### 8.3 防重复与过期

1. 点击请求携带 command_id，同一个 ID 重试返回原结果；同 ID 不同内容返回冲突。
2. Go 校验 game_id、turn_id、expected_version；接收后才生成骰子或移动。
3. VAD 开始一段新输入时撤销旧授权；转写被接受后，Go 签发仅保存在服务端的 action token，绑定当前局和版本。写工具只使用所属响应绑定的授权，迟到响应不能借用后续语音的授权。
4. 工具动作使用服务端生成的 command ID 去重；Realtime call ID 用于匹配 function output，不能单独作为业务去重依据。
5. 每轮 Realtime VAD 语音输入只允许一次主动写操作；掷骰后唯一走法的自动移动属于该次原子动作。用户可在灵矽播报时插话，新一轮输入会替换旧授权。
6. 同一段语音返回后的后续查询可读取新棋局，但不能据此获得第二次写授权。下一次语音输入才能签发新授权。
7. AI 回合由服务端触发，不消耗真人语音授权；AI 调度携带预期版本，过期任务直接丢弃。
8. 新局、语音超时、上游重连或解绑时撤销旧授权与绑定；迟到工具调用返回错误，不能改新局。

不承诺无限时长的 exactly-once。去重数据在本局存活期内有效；P0 进程重启后房间与去重记录一起失效。

## 9. 灵矽 Realtime 接入方案

### 9.1 服务端连接与鉴权

浏览器在用户点击“开启实时语音”后申请麦克风权限，将 PCM 音频发给同源 Go WebSocket。Go 使用服务端 API Key 和配置的模型名连接灵矽 Realtime；密钥不会进入网页、URL 查询参数或游戏快照。

配置项为 `LINGXI_REALTIME_URL`、`LINGXI_REALTIME_MODEL` 和 `LINGXI_REALTIME_API_KEY`。开发时放在被忽略的本地 `.env`，部署时放在服务器 `/etc/flytogether.env`。Go 启动后 `/api/config` 只返回是否已配置，不返回任何凭据。

每条 Realtime 连接初始化独立会话，收到 `session.created` 后，Go 下发模型、提示词、音频格式、服务端 VAD 和游戏工具；确认 `session.updated` 后才通知浏览器开始上传音频。任一会话只对应一个房间。房间状态由 Go 管理，灵矽连接由 Go 网关独占使用。

### 9.2 音频与全双工对话

浏览器 AudioWorklet 采集麦克风，转换为 16 kHz、单声道、signed PCM16 小帧。Go 把帧编码为 Realtime `input_audio_buffer.append` 事件。服务端 VAD 检测说话起止，配置 `create_response=false`；Go 在转写被接受后主动发送 `response.create`，启用语音打断。

会话输出模式设置为 `["audio"]`。灵矽返回 24 kHz PCM 音频增量及关联字幕；Go 和浏览器同时兼容 `response.output_audio.*` 与旧版 `response.audio.*` 事件。浏览器解码 PCM 并通过 Web Audio 排程播放。VAD 检测到新输入时，浏览器立即清除旧播放队列；已提交的棋步不会因此回滚。

### 9.3 游戏工具和动作授权

实时会话声明 `get_game_state`、`roll_dice`、`move_piece`、`use_prop` 四个项目工具。明确的中文掷骰、选子和使用道具指令由 Go 根据当前棋局先执行，再把服务端生成的 function call 与实际结果写回会话，请求灵矽只播报结果且禁止再次调用工具。这避免模型只说“起飞了”却没有执行动作。多个合法候选时追问，否定、规则询问和已起飞飞机的重复起飞不执行动作。

其余对话仍可由灵矽返回 function call；Go 在 `response.done` 后执行对应工具，将 function call output 写回会话并请求模型继续回复。所有写操作共用同一个房间规则入口和单轮授权。

Go 不接受模型提供的房间 ID、骰子点数、游戏版本或动作 token。语音转写被接受后，Go 为当前局和状态版本生成一次性授权；服务端根据响应绑定的授权执行工具，并通过 room 服务校验回合、合法走法和去重。取消或迟到响应不能执行旧动作。每轮语音最多完成一个改变棋局的动作。读操作返回的棋局状态与可走方案来自 Go。

真人游戏操作与浏览器点击共用同一规则入口。模型回答规则问题前先查询当前棋局；错误和歧义作为工具结果返回，模型不得把失败操作说成成功。

### 9.4 断线与降级

Realtime 连接断开时，Go 关闭当前上游会话并清除该轮写授权；网页提示语音断开，可点击继续游戏。真人操作和 AI 轮次只在 Go 中执行，不依赖语音在线。

已通过真实平台验证的项目包括：`lingxi-realtime` 模型、Bearer 鉴权、会话初始化，以及合成中文音频输入后的 VAD、转写、棋局查询工具和 PCM 语音回复。浏览器真实麦克风、扬声器回声、语音打断和家庭试玩仍需独立验收；合成音频联调不代表这些体验已通过。

协议依据：[灵矽 WebSocket 文档](https://linx.qiniu.com/docs/xrobot/platform/websocket)。

### 9.5 直接对话与独立回合播报

开始、继续游戏与刷新进行中的对局时自动连接，默认关闭唤醒门控；直接说指令，连续对话没有 30 秒超时。前端不展示唤醒词设置或待唤醒操作，清理旧浏览器偏好，并将旧房间切换到直接对话。保留旧协议字段以兼容已存在的客户端。关闭麦克风、暂停、结束和返回首页会释放采集资源。

没有对讲连接时，可用 `POST /api/rooms/{room_id}/announcement` 获取当前回合或胜利短句。Go 校验房间归属、局 ID 和回合 key，只从权威棋局生成文案；灵矽会话不输入麦克风、无游戏工具。合成前后再次校验回合，慢回复过期即丢弃。有限缓存复用相同名字的播报；生成繁忙可重试。浏览器等待骰子/走棋动画结束后播放，取消、静音或页面退出清理音频，不与对话重复播报。

实时回复的 PCM 使用有界队列，最多缓存 90 秒，只向 AudioContext 预排约 350～450 毫秒，避免正常快速生成被当作故障断线。达到安全上限只取消当前播报，保留连接；打断和停止同时清空已排与未排音频。音频上下文暂停时不继续预排，恢复后继续消费。

## 11. 接口与消息契约

本节接口均为项目设计，不是灵矽内置 API。实现时以契约为基础补齐 schema。

### 11.1 浏览器接口

| 接口 | 用途 |
| --- | --- |
| POST /api/rooms | 创建房间与本地操作者会话 |
| POST /api/rooms/new | 替换当前浏览器房间，旧房间结束，新房间进入准备阶段 |
| GET /api/session | 返回当前会话的房间完整快照 |
| POST /api/rooms/{room_id}/matches | 重新准备一局，新的 game_id 与库存 |
| POST /api/rooms/{room_id}/commands | roll/move/prop 及 start/pause/resume/end 的统一写入口 |
| POST /api/rooms/{room_id}/voice-settings | 兼容旧语音设置；网页迁移为直接对话 |
| POST /api/rooms/{room_id}/announcement | 鉴权后合成当前回合或胜利短句，返回 PCM 音频 |
| GET /ws/game?room_id=... | 完整快照、游戏事件和语音 UI 状态 |
| GET /ws/voice?room_id=... | 浏览器 PCM 音频帧、Realtime 事件与播放增量 |
| GET /healthz | Go 进程存活 |
| GET /readyz | 游戏服务就绪；语音能力单独标为 ready/degraded |

创建房间后签发不透明 HttpOnly Cookie。room_id 可以出现在路径中，但不是访问凭据；服务端必须校验 Cookie 对房间的控制权限。WebSocket 沿用 Cookie，并检查 Origin。

示例点击命令：

~~~json
{
  "command_id": "cmd-example-001",
  "game_id": "game-example",
  "turn_id": "turn-example",
  "expected_version": 12,
  "action": "move_piece",
  "arguments": { "piece_id": "red-bear" }
}
~~~

成功返回 command_id、当前 version、完整 snapshot 和本次 events。错误包含稳定的 code、面向人的 message 和 request_id；状态过期时提示刷新并获取最新快照。

错误码至少包括 ROOM_NOT_FOUND、NOT_AUTHORIZED、VOICE_BUSY、STALE_STATE、INVALID_PHASE、ILLEGAL_MOVE、VOICE_UNAVAILABLE、COMMAND_CONFLICT。

### 11.2 Realtime 游戏工具

| 工具 | 输入 | 输出与限制 |
| --- | --- | --- |
| get_game_state | 无 | 当前玩家、点数、棋子标签、版本、阶段、规则摘要 |
| get_legal_moves | 无 | 由 Go 计算的合法候选、后果和不可走原因 |
| roll_dice | 无 | Go 随机点数、自动移动或等待选择、真实状态；授权由服务端补入 |
| move_piece | piece_id | 校验后位移、跳格、飞行、撞机和终点结果；授权由服务端补入 |
| use_prop | prop_id | 校验模式、掷骰阶段、库存和适用条件后消耗一张道具；本轮不再自动掷骰 |

语音动作授权不会暴露给模型。写工具不接受自定义骰子点数或最终位置。AI 玩家回合不能经真人语音工具代替 AI 发起动作。

Go 将结构化结果作为 `function_call_output` 写回 Realtime 会话。Go 直接向网页广播棋局，不依赖灵矽把游戏状态自动转发到网页。

### 11.3 游戏推送

每次广播使用统一包络：

~~~json
{
  "type": "game.updated",
  "room_id": "room-example",
  "game_id": "game-example",
  "seq": 31,
  "state_version": 13,
  "command_id": "cmd-example-001",
  "snapshot": {},
  "events": []
}
~~~

snapshot 与 events 在真实实现中填完整。P0 棋局小，每次发送全量快照；避免同步增量补丁。seq 为房间消息序号，state_version 只在棋局变更时增长；字幕等消息不能伪造棋局版本变化。

重连时先获取快照，按 game_id 与 seq 丢弃过期消息，直接对齐棋子位置，不重播断线期间的完整动画。声音不落入重放队列。

## 12. AI 对手与提示词

### 12.1 策略

AI 与真人使用相同骰子规则与合法候选。先用简单评分：获胜 > 到达终点 > 撞机 > 飞行/跳格 > 前进。平分使用稳定次序，便于调试。

支持难度调节时，显式选择简单或普通策略；不暗改骰子、不伪造结果。P0 只交付一种策略。

### 12.2 主持人提示词要求

- 你是“一起飞”的家庭主持人，称呼使用本局昵称和棋子标签。
- 执行操作前查询真实状态；选择只能来自合法候选。
- 骰子由工具生成，不根据用户要求修改。
- 选择不明确时询问；不替孩子做未确认的多选决策。
- 讲解引用工具提供的原因与当前 ruleset，不凭记忆补充其他飞行棋变体。
- 收到工具失败时说明失败，不能宣称已完成。
- 单次回复默认一到两句，避免每次都重复规则。
- 听到日常聊天时不移动棋子；关键动作必须有明确操作意图。

提示词是交互约束，真正的权限与规则仍在 Go 中执行。

## 13. 部署、配置与数据

### 13.1 P0 部署

本机可运行 Go 服务和网页；公网部署使用 HTTPS/WSS 同源提供页面与游戏 API。麦克风由浏览器授权。

音频由 Go 建立到灵矽的 Realtime WebSocket 上游连接。反向代理需允许 WebSocket 长连接。

只运行一个 Go 实例；SQLite 与运行时锁共同维持权威状态，不支持多副本负载均衡。

### 13.2 配置类别

| 配置 | 管理方式 |
| --- | --- |
| 本机监听地址、公开 URL | `.env` 或部署环境配置 |
| Realtime WebSocket 地址 | `LINGXI_REALTIME_URL`，默认使用平台实时接口 |
| Realtime 模型名 | `LINGXI_REALTIME_MODEL`，服务端会话配置使用 |
| Realtime API Key | `LINGXI_REALTIME_API_KEY`，只由 Go 进程读取 |
| 超时、队列长度、日志级别 | 有默认值，启动时校验范围 |

真实凭据不进入 Git、网页构建产物、URL 或日志。会话 ID 等诊断值按需要截断或哈希。日志默认只记录动作与时延，不保存原始录音或完整对话；平台侧聊天保存和记忆设置需要单独确认。

创建新局保留房间操作者会话，撤销旧局语音授权并更新绑定。房间超期按配置清理；关机保留已提交的 SQLite 数据，重启恢复为暂停。关闭服务时断开上游、撤销绑定并有序关闭 WebSocket。

## 15. 验证与验收

### 15.1 必要自动化验证

- 规则表驱动测试：起飞、无路可走、六点奖励、跳格后飞行、终点超步、叠子与最终落点撞机、胜负。
- 地图校验：各方路线连续，跳格/飞行映射有效；公共格与本方航道的碰撞范围正确。
- 命令一致性：重复 command_id / action_token 不再次掷骰；同 ID 不同请求冲突；过期版本和旧 game_id 被拒绝。
- 会话隔离：解绑、重连与新局后旧会话工具不再修改状态；未经语音授权的游戏写工具不能调用。
- 点击、语音与 AI 竞争：同一版本最多提交一个有效动作。
- 动画结果与服务器最终快照一致，页面重连不重复播放旧声音。

### 15.2 人工试玩

- 在预期的家庭摆放距离和扬声器音量下测试持续语音、打断与播放回声。
- “走小熊号”“最前面的”“哪架能撞爸爸”都能完成选择或明确追问。
- 骰子、位移、字幕和播报一致；误识别不导致隐蔽的连续动作。
- 点击操作在灵矽断线时仍可完成一局。
- 短讲解易懂，不出现每一步都等待长篇播报的节奏。
- 邀请家长和孩子试玩时记录实际观察，未试玩前不宣称儿童识别体验已验证。

延迟目标是设计指标：有效操作在提交到 Go 后尽快更新棋盘；从说完话到实际反馈的完整时延需记录实测中位数和慢例，不在未测量时承诺固定毫秒数。

### 15.3 三分钟演示脚本

1. 介绍家庭场景并打开快速模式或标注的演示局面。
2. 玩家说“掷骰子”，展示真实点数与一致播报。
3. 玩家问“哪一架能撞爸爸”，展示合法方案和高亮。
4. 玩家选择昵称，展示移动、撞机与简短反馈。
5. 展示 AI 自动回合，询问一次“为什么不能走”。
6. 说明当前已验证能力与仍待改进事项；准备真实链路录屏应对现场网络故障。

### 掷骰展示

`rolled` 事件携带该次独立的 `dice_rolls`，防止连续 AI 回合的最终快照覆盖前次点数。网页按事件 ID 去重并排队展示 3D 弹窗；点击、语音和 AI 使用同一事件链路。动画仅展示结果，不决定随机数；支持减少动态效果偏好。

### 家庭房间状态与难度（#8）

Room 提供 `name` 和 `status`：`waiting → playing ↔ paused → ended`；waiting 也可直接结束。正常胜负使用棋局 `phase=finished`，保留冠军信息，用户仍可结束或重新准备。网页首页负责创建与配置，提交后进入 `/play` 对局页。新房间先由服务端进入 waiting，网页随创建流程显式发送 start；重新开局直接以 playing 准备。准备、暂停与结束状态仍由服务端控制；`/play` 刷新返回同一应用入口。

控制命令沿用 Cookie、game_id、command_id 去重和房间锁。暂停、结束同步撤销语音授权、清除 busy 并停止 AI；继续不恢复旧授权，按自动语音偏好重新连接并申请麦克风。客户端断开待建立连接时，晚到的麦克风流立即停止，旧连接事件不会重建语音。握手提前断开会立即报错，停止播报后丢弃旧 response_id 的音频和字幕。上述连接行为通过模拟与实际 Chrome WebAudio/WebSocket 回归；真人有限样本已确认操作与打断，更多设备、噪声和回声场景由 M3 继续验收。

`difficulty=easy` 在合法走法中随机选子，不用道具；`normal` 使用走法评分和辅助道具；`hard` 使用评分及真实目标的攻防道具。所有难度共用随机骰子与合法走法，没有修改点数或真人规则。当前为家庭同屏房间，跨设备邀请仍属后续范围。


## 新手指南与落点预览（#18）

首次进入进行中的对局时显示三步引导，完成或跳过后在当前浏览器保存 `fly-tutorial-v1`；顶栏始终提供重看入口。指南不提交游戏操作，打开时阻止点击和空格掷骰，停止对话采集与独立播报；首次、未完成时刷新和手动重看都保持安静。完成或跳过后按自动语音偏好连接，手动关闭的偏好保留。

手动选子先产生本地预览，使用 Go 已计算的 `legal_moves`：`from/to`、`launch/jump/fly/finish`、`captured` 与 `blocked`。前端只把最终位置映射到棋盘坐标，不重复计算跳格、撞机或护盾规则。3D 使用同一场景中的可复用落点标记与连接线，2D 降级使用 SVG 标记；连线指向最终位置，不作为逐格路径承诺。

预览绑定 `game_id + version + piece_id`，不修改飞机、库存或版本，也不播放移动音效。点击“确认飞行”才提交已有 move 命令；取消、换选不写服务端。暂停、新局、状态版本变化或其他输入完成操作时清除过期预览，确认前再次检查局和版本，服务端仍负责最终校验与去重。骰子弹窗和未完成动画期间不能预览选子，明确语音/AI 操作沿用原有执行与动画顺序。


## 引导静音、幸运骰投掷与结束导航（#19）

幸运骰在 Room 锁内将使用道具和 `RollRandom` 合为同一个命令；点击、语音和 AI 共用两次实际随机点数，生成同一 `rolled` 事件。一个 command_id 重试不会重新扣卡或重掷，一个语音授权不能继续提交第二次投掷。规则引擎的底层用卡操作仍可独立验证，应用层使用幸运骰即执行双骰。

主持人指令补充本次新事件，同时写入服务端系统上下文；每次替换上次临时上下文，避免旧提示累积。只有本轮 `rolled` 才可播报新点数，不能把保留在状态中的历史 dice 说成刚掷出的结果。已观察到“幸运骰”转写成“幸运头”，在明确使用指令中支持该别名，否定与询问优先走只读。

客户端结束命令成功后跳转首页，失败保留棋盘并显示原因。首页继续入口仅对未完结的 playing/paused 游戏展示；正常胜利仍保留庆祝和重新准备入口。


## 灵矽教练与连续确认（#20）

Room 的 `coach` 是共享建议，包含独立提案 ID、game_id、version、player_id、一个已存在的合法 Move、说明和有限风险评估。`coach` 命令的 choice 支持 best/next/safe/previous/cancel，只改变 Room seq；不改变棋局版本、历史、飞机、骰子或库存。前端经现有游戏 WebSocket 收到提案，用已有 3D/2D 落点标记和 MovePreview 展示，播报期间也能看见预览。手动选飞机会取消服务器建议并回到原有本地预览。

Go 在已合法的 Move 上作比较。普通推荐复用 BestMove；风险评估在深拷贝上实际执行候选走法，枚举每位对手普通 1～6 点的合法回应，统计能撞回这架飞机的对手/点数组合，包含本次撞机和护盾效果。安全比较先选较少受威胁的候选，再以原推荐顺序打破平手。该估计不模拟间隔回合、对手选择或道具，不是概率或必胜判断。

语音“帮我选”“另一架呢”“安全一点”“刚才那个”先由服务端解析，工具输出当前提案；“就它”、明确确认及指定合法飞机才可走棋。询问和否定保持只读，取消只清预览；限定范围内的“另一架”ASR 同音误写仅在已有建议时兼容。每次提案也占用本次语音授权，不能在同一话语里先推荐再自动移动。

`confirm_coach` 另校验提案 ID 和局、版本、玩家，再调用原 Move 并复用 command_id 去重。相同棋局版本下更换提案也产生新 ID，旧确认不能误用新建议。暂停、结束、新局、其他实际操作及语音断开清除建议；过期的指代确认不会降级成掷骰。纯点击可完成同样的推荐、比较、取消与确认，不依赖平台或麦克风。


## 免注册联机与结算（#21 / #22）

创建参数 `network:true` 强制等待，总席位 2～4；`ai:true` 将最后一席交给机器人，其余为真人。房主占第一席位，其余通过 `/#join=房间ID.随机凭证` 入座。凭证在 URL fragment 中，不随首页 HTTP 请求或 Referer 发出；仅有房间 ID 不能读取房间或加入。加入通过同源 POST 校验凭证，服务端生成 HttpOnly / SameSite=Strict Cookie，生产 HTTPS 使用 Secure；Cookie 只在服务端映射席位，浏览器不能提交 actor 来冒认别人。

| 接口 | 权限与效果 |
| --- | --- |
| `POST /api/rooms/{id}/join` | 邀请凭证+昵称，等待阶段领取空位；原会话可回原席位 |
| `POST /api/rooms/{id}/ready` | 当前成员修改自己的准备状态，房主默认准备 |
| `POST /api/rooms/{id}/leave` | 准备阶段客人释放席位；开局后断线保留席位 |
| `POST .../commands` | start/pause/resume/end/replay 限房主，其余限当前席位；去重绑定 actor |
| `GET /ws/game` | 每个连接收到自己的 `me`；广播公共席位在线/准备状态，不广播会话凭据 |
| `GET /ws/voice` | 当前席位语音租约；每次语音授权与工具写入再次检查 actor、局、版本和单次令牌 |

房主开局必须所有真人席位已占用、已准备且有在线游戏连接；机器人固定标记 occupied/ready/online，并带 `robot:true`，不创建虚拟浏览器 Cookie 或连接。邀请分配会跳过机器人席位，并拒绝与机器人重名。多个标签页按会话聚合在线；关闭最后一个连接显示离线，15 秒心跳与 5 秒超时清理失联连接。浏览器离线立即停止提交，重新连上并收到权威快照后才开放点击。首版不自动跳过掉线玩家，不转让房主；可暂停等待其回来。

Room 的语音租约防止旧连接断开时清除新连接的动作授权；回合改变时撤销旧席位写入权。进程默认最多 4 条 realtime 对讲上游连接（可配置），每房间一条；同文案的主动 TTS 请求合并并共享有界缓存。邀请信息不发送给上游游戏工具。邀请是入座凭证，已入座身份来自 Cookie；主动结束后拒绝新加入，再玩保留原邀请。

`Player.stats` 在真实 RollValues / apply / UsePropOn 成功时累计，值类型不会被教练克隆共享。幸运骰计一次 roll，盾抵消不计 capture；统计不依赖最近 24 条事件。正常获胜在动画与庆祝后呈现，刷新只读取现有值；replay 是去重命令，保留规则/玩家并清零所有状态，联网重新准备。同屏主动结束仍回首页。

房间、邀请、Cookie 映射、本局计数与点击命令去重已持久化到 SQLite，重启恢复为暂停；语音授权、建议和连接不恢复。原席位需要原浏览器 Cookie，不支持跨设备找回。保存事务、异常隔离、备份见 [SAVES](SAVES.md)；三类声音控制和语音资源边界见 [QA-RELIABILITY](QA-RELIABILITY.md)。


### 联网机器人扩展（#23）

沿用已有一个规则 AI（最后一席）与 `Room.AI()` 调度：轻松随机选合法飞机且不用道具，普通优先合法好走法并用辅助道具，挑战会攻击和防守。骰子仍由相同 Go 随机源生成，不依赖灵矽 API。等待、暂停和结束不调度机器人；再次开局复用机器人标记、名字与难度，真人客人重新准备。

“添加机器人陪玩”表示占用一个玩家席位；“灵矽语音助手”是不占席位的主持/讲解/真人操作入口。联网机器人回合没有真人会话可取得 actor 权限，真人点击和语音仍不能代操作该席位；机器人仅由 Go 内部调度行动。


## P1：陪玩、预设与按需棋盘（#26～#28）

陪玩偏好属于浏览器，保存在localStorage；realtime握手携带枚举style/frequency，连接内可通过受校验的companion_preferences更新，取消旧主持但不重连麦克风、不改变棋局。输出式TTS请求携带相同偏好，Go决定是否需要播报；quiet返回204，明确提问和操作仍可响应。风格不放宽动作授权。

常见轮次查询由Go解析；明确操作完成后，以已提交事件生成待读文案，避免模型重新解释起飞卡、点数、位置和昵称。自由对话仍需模型，实际样本与误差范围见 [QA-P1](QA-P1.md)。

Options.preset选择gentle/classic/custom；服务端将固定模式和道具条件规范化。State保存preset和实际rules说明，legalMoves、机器人与语音选择共享CanLaunch等Go规则。亲子允许5/6起飞，只有6加掷；经典四架全到无道具；原自定义保持兼容。数据库schema2阻止旧程序误读新规则，升级前已备份。

BoardLoader通过React.lazy按需导入Board/Three.js，Suspense显示加载提示，局部错误边界提供重新加载入口，保留其余页面。首页不发出棋盘模块请求；首次进入下载，返回再进复用。加载量实测和失效恢复范围见QA-P1。

## 家庭飞行员与跨局历史（#29）

同一个 HttpOnly、SameSite=Strict Cookie 用于席位和本浏览器资料库，HTTPS时Secure，访问会话/资料时续期一年；房间闲置保留仍默认7天。无账号、全局用户ID或跨设备找回。最多12份内置头像/昵称档案，API按Cookie隔离，服务端解析本人ProfileID再生成名字和头像。网络房主不能替朋友绑定档案，客人通过邀请页选择自己设备的资料；同屏房间可绑定多位家人。

档案ID保留在房间私有配置中，个性化HTTP/WS快照只返回本人可用的绑定；公开棋盘只有当局名称/头像。再玩保留当局配置，新建游戏重新解析当前资料，改名/删档案不改写旧快照。头像限六种内置ID，无图片URL或上传。

SQLite schema3：`family_profiles(session,id,name,avatar)` 与 `family_history(session,game_id,completed_at,payload)` 不依赖rooms外键。`database.save`在确认最终动作之前，为自然完成且非演示的棋局写入结果快照；房间/去重命令/战绩共同提交，失败共同回滚。结果按浏览器+gameID唯一，重复命令、结束后保存或启动加载不会重复计数。联网每个真人各收一份相同对局事实，仅自己的条目含档案关联；机器人无资料库。

GET `/api/family` 返回本人档案、总记录数与最近50局；POST `/api/family/profiles`、`/profiles/{id}/delete`、`/history/clear` 提供资料编辑与独立清理。最近50局统计只聚合返回的已完成记录，不从24条滚动事件日志推算。清空将payload置NULL而保留去重收据，避免旧房间复写；房间超期或删除不级联删除战绩。仍是单实例SQLite，资料和备份按敏感数据管理。

## 语音动作确认与动画（#30）

明确指令在请求播报前执行Go规则并提交。含糊骰子话语、否定和掷骰问句只读；每条新转写清理上一段朗读上下文。对于本地已处理的回合，除发送tool_choice=none，还在网关拒绝后续模型工具，防止朗读阶段意外多操作。

语音WS的game_action含当前授权浏览器的权威Room快照和Go事实文案。前端VoiceClient把它交给App.accept，与/ws/game共用序号/实例去重及presentation事件队列；双通道不会重复掷骰或播放动画，棋局通道延迟时语音确认仍可展示实际投掷。它不创建浏览器端随机点数或补写动作；模型的自然语言不能替代确认，停止播放不回滚已提交棋步。

## 显示偏好与键盘（#31）

`fly-experience`仅存本浏览器，合法值为board:auto/flat、motion:system/reduced；未知值回默认，系统偏好change事件与同浏览器storage变更实时同步。设置面板和两种棋盘分别lazy加载；共用BoardFrame/SVG布局，轻量入口不引入Three。立体切换为轻量时卸载FlightScene，执行原有几何/纹理/材质、RAF、observer与context清理，不重启Go棋局。

有效减少动画取显式设置或系统偏好。CSS通过html[data-motion]禁用过渡/装饰，Three逐帧读取当前标志，骰子停止旋转、飞机直接到目标、合法/落点高亮不脉动，庆祝保留文字并不创建粒子。presentation仍按服务端真实事件先骰子后飞机，只缩短过渡，键盘模式的静态骰子等待确认，语音和点击沿用自动继续。键盘/指针事件更新当前输入方式，真实用户转写到达时退出键盘确认模式，避免先按过Tab后纯语音被弹窗阻塞。

所有入口保留原生按钮。useDialog统一showModal、Tab边界与异步焦点恢复；新焦点已经进入预览/控件时，旧cleanup不抢回。快捷键只在对局主区域且无弹窗/输入/按钮焦点及合法canAct状态下执行，数字先只读预览，Enter仍提交Go命令，不改变授权、版本或去重。页面跳转定位main，SVG与文字操作保留编号/状态辅助。


## 管理排障（#32）

`/admin`独立lazy界面，`/api/admin/*`独立会话中间件，32字符以上密钥仅在服务器；随机会话令牌只存哈希，8小时内存过期/退出撤销，HTTPS Cookie为HttpOnly/Secure/Strict。管理员GET查询与玩家身份隔离、同源和有界参数校验；不会向普通玩家返回记录内容或启用管理员操作。

schema4在原SQLite增加`diagnostic_matches`和`diagnostic_events`。每次`database.save`在同一事务保存去私密身份字段的game.State、最新对局信息和新增游戏事件；按game_id/event_id或状态序号去重。旧存档建立记录起点，重开保持上一局，rooms删除不级联删除排障表；过期查询先排除，启动/小时清理。语音传输为独立有界写入，失败只增加计数；Go事务写入失败仍回滚棋局。

Bridge只提交显式DTO，包括新生成session_id、上游input_id/response关联、最终转写/assistant消息、工具完成/拒绝、第一段PCM到达与连接生命周期。输出式TTS只记生成结果，不持久化音频；浏览器故障只允许固定枚举、原席位和当前棋局，短窗合并。没有序列化原始HTTP/WS/工具包或授权信息。自由文本限制与常见凭据屏蔽、可关闭新文本、默认7天保留。详见 [后台](ADMIN.md) 与 [验收](QA-ADMIN.md)。

## 道具与Realtime补充（#36 / #37）

新建趣味局8种道具，回旋镖/救援/护航由同一Go事务执行，event附prop_id及effects（piece_id/from/to/kind）。浏览器展示队列只播放新事件，不发送附加命令；平面路径/中央提示及音效共用真实事件，DOM/CSS特效不创建Three renderer。旧库存不补发，新预设规则标记family-props-v3/family-gentle-v2，已保存棋局保留自身标记。

语音每轮更新配置后，等待instructions匹配的session.updated，再发response.create，避免旧播报串入；8秒未确认提示重连，权威游戏结果不回滚。响应依然绑定原语音动作授权，打断后旧确认不触发新生成。

真实上游已验证原生type:mcp配置、远端工具导入/调用/结果续答，但生产游戏仍走既有function授权链路，未来MCP写工具须继续校验房间/席位/轮次与幂等。MCP完成可能晚于response.done，集成不能把生成结束当工具完成。详见[接入核对](LINGXI-MCP.md)。

## 真人暂离托管（#38）

成员的delegated、auto_delegate、原因与控制代次随房间事务保存，真人Player.AI不改变，统计归原席位。每次控制切换递增棋局版本，撤销该席位旧语音lease与grant；后台Go调度器从当前phase接续，托管只随机掷骰/选择已有合法走法，禁止为真人挑新道具。真实托管棋步带标记，管理与比赛工具共用锁及持久化边界。

只统计已认证成员的游戏WS订阅，多标签页合并；页面隐藏不等于离线。预先同意后经过ROOM_DELEGATION_SECONDS才自动切换，重连取消尚未完成的等待，开始托管后需明确接管；没有在线真人时不代玩。临时倒计时不落盘，重启暂停，之后重新计算。

回位允许当前控制代次内的较旧棋局版本，避免托管推进时不断冲突，但拒绝更早控制代次的迟到接管。所有写入仍在房间锁中提交，保留真实已掷点数/已走棋步；幂等重试只读现状态，不重复执行。新局清除托管及同意，schema6阻止旧程序忽略托管角色。
