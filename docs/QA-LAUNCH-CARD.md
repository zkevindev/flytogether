# 起飞卡直接起飞验收

更新：2026-10-24。起飞卡的行为改为：明确选择一架当前玩家仍在机库的飞机，使用后立即移动到起飞位；不要求掷骰。该动作消耗起飞卡、记录一次道具使用和一次起飞，并占用本回合掷骰前的道具位；玩家仍可继续掷骰。

语音只说“使用起飞卡”时，灵矽先询问选哪架；同一语音连接的下一句可只报飞机名字。也可一次说“使用起飞卡让小熊号起飞”。服务端按当前玩家的机库飞机名单校验，未指定、指定他人、重复提交或已飞离机库的飞机不会被猜测或重复移动。旧存档中已经启用的旧版起飞卡保留原回合效果；新使用按本页直接起飞规则处理。

## 验收

- `go test -race ./...` 与 `go vet ./...` 通过。覆盖目标只限当前玩家的机库飞机、飞机立即抵达起飞位、道具/起飞统计、棋局事件与占用本次道具位；骰子不会被起飞卡伪造。
- 前端单测、TypeScript 检查和生产构建通过。
- 实际Chrome道具流程：从道具口袋选起飞卡，再选一架真实机库飞机；页面显示飞机从机库到起飞位的效果与起飞音效，Go快照中该飞机 `progress=0`、起飞统计增加、掷骰统计仍为0。之后正常掷骰，3D骰子弹窗展示真实结果，棋局进入走子阶段，道具位仍按规则锁定。
- `test:props:browser` 的11项既有本地/联网道具流程通过，浏览器无错误、麦克风请求为0。截图见 [launch-direct.png](images/props/launch-direct.png)，来源与哈希见 [manifest.json](images/props/manifest.json)。
- 语音解析单测覆盖“只说起飞卡后再报小熊号”以及“一句话明确卡和飞机”的指令解析。此轮没有现场真人麦克风或真实灵矽音频输入验收；真实上游音频识别不在本次结论中。

复跑：先运行本地 Go 服务，再执行：

```sh
go test -race ./...
go vet ./...
npm --prefix web run test:unit
npm --prefix web run build
QA_BASE_URL=http://127.0.0.1:8080 npm --prefix web run test:props:browser
```
