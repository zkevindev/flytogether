# 演示与发布运行手册（#3）

这份手册用于三天两晚 Hackathon 的现场演示和小版本发布。它不代表没有执行过的噪声、回声、切网或长时间真人监听验收已经通过；这些仍由 [Issue #3](https://github.com/zkevindev/flytogether/issues/3) 跟踪。

## 三分钟产品讲解

三分钟用于说明完整产品链路，不承诺三分钟内自然随机对局必然结束。骰子、撞机与胜负都来自实际 Go 规则，不使用固定点数、编辑数据库或注入棋盘状态。

| 时间 | 演示内容 | 操作与讲解 |
| --- | --- | --- |
| 0:00–0:25 | 产品定位 | 说明家长和孩子可以同屏或各用一台设备，点击玩法不依赖灵矽。 |
| 0:25–0:55 | 创建房间 | 选择 2～4 个席位、亲子/经典规则和棋盘；说明邀请房间免注册、每台设备只控制自己的席位。 |
| 0:55–1:40 | 一次真实回合 | 开局，真实掷骰；有合法走法时选棋子。可以介绍一个可用道具。骰点不合适就继续下一回合，不重掷或预设结果。 |
| 1:40–2:15 | 语音与权限 | 如果语音已配置且现场网络可用，展示自然语言查询或当前回合播报；否则说明点击操作仍可完整继续。真实语音不在浏览器显示或输入密钥。 |
| 2:15–2:40 | 家庭大屏 | 在联网房间复制电视大屏链接，用另一浏览器打开，展示棋盘、骰点、棋步同步；大屏不能操作比赛，也不申请麦克风。 |
| 2:40–3:00 | 续玩与结算 | 展示首页保存/续玩，或用一局已经自然结束的记录展示统计与回顾卡；手动结束不伪造胜者。 |

### 开场前准备

- [ ] 选用比赛专用测试房间与昵称，不使用家庭真实个人资料；确认演示完可删除测试房间。
- [ ] 一台主持设备和一台访客/大屏设备已连到同一网络；大屏浏览器不登录主持人的玩家席位。
- [ ] 如果要展示灵矽，先在本机或服务器外部配置中确认语音已启用。检查时只看 `/readyz` 的 `voice_configured` 布尔值，不复制、截图或讲出密钥、服务端环境文件或管理密钥。
- [ ] 语音不可用时采用点击流程；不现场重启服务、不调整防火墙、不改生产环境密钥。
- [ ] 仅在比赛授权的公开演示环境操作；生产房间、家庭档案和真实历史不用于测试。

## 发布前检查

小切片通过关联 Issue 的独立 PR 进入 `main`。合并前检查：

- [ ] PR 只解决一个可验收 Issue；描述引用 Issue，Issue 评论记录 PR、验收结果和剩余事项。
- [ ] GitHub Actions 的 Go 与前端构建/测试通过；Codecov 状态正常。失败或未运行都不写成通过。
- [ ] 本地 `go test -race ./...`、`npm --prefix web run test:unit`、`npm --prefix web run build` 通过；可见改动还要运行对应 Chrome 浏览器回归。
- [ ] 真实灵矽联调、合成音频、真实麦克风、模拟故障分别记录来源和范围；不拿截图或单元测试代替现场验收。
- [ ] 执行部署前确认当前线上版本、服务健康及数据库路径；使用仓库外部署配置，不在终端记录、PR、Issue、截图或共享文档输出凭据。
- [ ] README、路线图、验收文档与截图注明对应版本；截图不含地址令牌、Cookie、API Key、儿童个人信息或后台密钥。

## 演示数据备份

房间数据库含浏览器/房间凭证；若服务器启用了语音转写记录，也可能含对话文本。备份按敏感数据保管，放在 Git 仓库、发布包和公共网盘之外。

在已授权服务器上，按 [SAVES.md](SAVES.md) 提供的 SQLite 在线备份脚本执行。先在仓库根目录：

```sh
python3 scripts/save_backup.py \
  --database /var/lib/flytogether/games.db \
  --output /安全备份目录/flytogether-演示前-日期.db
```

脚本拒绝覆盖、使用 SQLite backup API 一并读取 WAL 中已提交数据、执行 `quick_check`，并以 `600` 权限写入。备份输出应位于加密或权限受控的目录；应单独记录备份时间、程序提交和 schema 版本，不把数据库复制到本仓库。

恢复前须确认使用与备份 schema 兼容的程序版本。服务停止后保留当前 `.db`、`-wal`、`-shm` 现场，再恢复备份、设置服务属主/权限，启动后检查 `/healthz`、`/readyz` 与原浏览器会话。完整恢复命令和身份边界见 [SAVES.md](SAVES.md)。备份不是回滚测试；现场恢复前先在隔离副本演练。

## 发布与回滚

仓库的 [部署脚本](../scripts/deploy.py) 通过仓库外配置构建并上传版本目录，更新 `current` 符号链接，重启 systemd，并检查本机 `/healthz`。脚本**不会自动回滚**失败版本，也不会自动备份/恢复数据库。公网变更需由已获授权的发布者操作，PR 合并本身不触发部署。

发布记录至少保存：

- PR/Issue、合并提交、Actions/Codecov 结果、对应构建目录名。
- 变更前的 `current` 目标、应用健康检查、数据库 `quick_check` 和仓库外备份位置。
- 发布后 `/healthz`、`/readyz`、TLS 页面访问、版本/静态资源与基本游戏流程核对结果。

若新程序健康检查失败，不要反复部署或删除数据库。先停止服务并保存故障日志及数据库现场；恢复必须按以下顺序由发布者执行：

1. 确认上一个发布目录和一份与其兼容的数据库备份仍可读。
2. 停止 `flytogether`，另存当前 `.db`、`-wal` 和 `-shm` 文件；不要在服务运行时覆盖数据库。
3. 将 `current` 指回上一个已验证的发布目录。若新版本已经升级 schema，先恢复发布前数据库备份；不能让旧程序直接打开新 schema。
4. 检查数据库属主和 `600` 权限，启动服务，验证 `/healthz` 与 `/readyz`，再用原浏览器确认房间/棋局快照。
5. 记录回滚提交、数据库备份标识和失败症状；不在公共 Issue 粘贴日志中的凭据或真实玩家资料。

回滚会回到备份时刻，之后的对局写入可能不在恢复数据中。当前安装脚本没有自动蓝绿切换、探活失败自动恢复、定期异地备份或自动恢复演练，发布前必须为这些边界留出操作时间。

- 项目采用 MIT License，许可证全文见仓库根目录 [`LICENSE`](../LICENSE)。

- 新增图片、音效、字体、视频或代码时，在引入 PR 记录原始 URL/仓库、版本/作者、许可证、改动方式和最终文件路径；没有明确授权的素材不得用于公开发行。

## 本分支自动验收记录

2026-10-24，在独立 worktree、localhost 服务和隔离 SQLite 数据库执行。测试房间与数据未写入线上环境：

- `go test -race ./...`：通过。
- `npm --prefix web run test:unit`：通过，包含 replay-card 与 voice-readonly 单测。
- `npm --prefix web run build`：通过；Vite 提示一个 bundle 超过 500 kB，未阻断构建。
- `npm --prefix web run test:network:browser`：通过。隔离浏览器完成双人自然胜局、刷新恢复/回顾，以及三人与四人席位流程；浏览器无 console error。
- `npm --prefix web run test:network:bot`：通过。验证双人/三人真人与机器人混合流程、机器人自然胜局与回顾、机器人用道具、座位上限及旁观只读权限。语音未配置时，WebSocket 权限断言按真实服务的 503 行为核对；已配置时检查未授权 403。
- `npm --prefix web run test:props:browser`：11 个用例全部通过，覆盖八种道具、联机道具流程、重复请求幂等性及无麦克风/WebGL 额外资源。

上述回归是隔离的自动化桌面浏览器/规则验证，不替代真实手机后台挂起、Wi-Fi/蜂窝切换、麦克风噪声/回声/距离、长时间连续监听或更多真实灵矽时延样本。服务未因此部署到公网。
